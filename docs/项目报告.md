## 1. 项目概述

### 1.1 背景与问题

编程与理论知识的学习周期长，容易出现「计划写了却不执行、测过一次就以为掌握、错题无法闭环」的情况。通用聊天机器人可以答疑，但不会持久记住某位同学的目标、掌握度和复习节奏；在线 OJ 可以判题，但通常与个人学习目标、知识点检测相互独立。

StudyMate 面向上述缺口，做一个**可在本机完整运行**的 AI 学习监督系统：计划、检测、复习、教学对话和 C++ 练习写在同一套用户数据里，由后端决定「今天该做什么」，模型只在用户主动触发时参与生成与讲解。

### 1.2 项目目标

1. 用学习目标驱动每日任务，而不是每次从空白对话开始。
2. 检测与复习使用固定题量与可解释的掌握度、间隔规则，避免一次高分被记成「已经精通」。
3. 题库与知识点学习两条线并存：导入题目、写代码、隔离判题；判题对错不由大模型决定。
4. 账号隔离与密钥隔离：浏览器不持有用户编号，也不持有 DeepSeek 密钥。
5. 评委或同学克隆仓库、按 README 安装后即可运行，不依赖作者电脑长期开机。

### 1.3 完成范围（对应版本 0.9.0 / 第 9 阶段）

已实现：注册登录、学习目标与计划、五题知识检测、掌握度事件、复习队列与复习检测、题目/知识点 AI 讲解、AI 导师、题库与错题、草稿与提交、Docker C++ 判题、学习档案与主题。

未实现（报告中如实说明）：AI 学习课堂页、学习汇报正文、题目维度的间隔复习（开发文档中的 8.4）。

## 2. 需求分析

### 2.1 用户与场景

| 角色 | 典型行为 |
| --- | --- |
| 学习者 | 注册后建立目标，生成今日计划，完成任务后检测，到期复习，向导师追问，在题库写 C++ 并查看判题 |
| 验收者 | 按 README 启动，走通注册、计划、检测、复习、导入题目与判题（若已安装 Docker） |

### 2.2 功能需求摘要

- 账户：注册、登录、退出；会话 HttpOnly Cookie；CSRF；业务接口不接受客户端传入的 `user_id`。
- 目标与计划：目标的创建、编辑、暂停、恢复、完成、删除；同一目标同一天仅一份有效计划；重新生成保留历史与原因。
- 检测：任务完成后生成 5 道题；客观题后端评分；简答题由模型评分；提交后写掌握度事件并更新复习间隔。
- 复习：到期队列；开始复习生成针对性 5 题；未提交试卷可复用；通过后间隔按 3/7/14/30 天延长，低于 60 分缩短为 1 天。
- 讲解：检测/复习题目可请求 AI 讲解；复习页可进行知识点讲解与追问。
- 导师：会话落库；发消息才调用模型；结合目标与掌握情况；导师对话不直接改掌握度。
- 题库：导入题面与测试数据；可选 AI 分析分类；草稿自动保存；提交为 `unjudged`；Docker 判题；错题由用户标记或判题结果驱动练习状态。
- 非功能：打开页面不调用模型；测试使用假模型，不写正式库；判题失败不得退回本机编译。

### 2.3 非功能需求

- 安全：密钥仅在后端；判题容器无网络、只读根文件系统、非特权、资源上限。
- 可复现：SQLite 单文件；Windows PowerShell 安装步骤写在 README。
- 隔离：用户之间不可读写他人目标、检测、提交与判题结果。

## 3. 总体设计

### 3.1 逻辑架构

```text
浏览器 (React + Vite :5173)
        │  同源 /api （开发代理）
        ▼
FastAPI (Uvicorn :8000)
        │
        ├── SQLite  studymate.db
        ├── DeepSeek API（仅用户触发的生成/讲解/导师/分析）
        └── Docker  studymate-judge:1（一次性容器跑用户 C++）
```

前端不直连数据库，也不直连 DeepSeek。局域网访问时，其他设备只打开 5173，由 Vite 把 `/api` 转到本机 8000。

### 3.2 技术选型理由

| 选型 | 理由 |
| --- | --- |
| FastAPI + SQLModel | 接口文档自动生成，模型与表结构同一定义，适合课程周期内迭代 |
| SQLite | 零运维，数据文件明确，便于演示与备份；不提交个人库到 Git |
| React + Vite | 热更新快，TypeScript 约束页面状态 |
| DeepSeek 兼容 OpenAI SDK | 密钥与超时集中在后端环境变量 |
| Docker 判题 | 与宿主机编译器隔离，限制网络与权限，避免「在老师电脑上直接 g++」 |

### 3.3 主要数据对象

- 用户与会话、学习目标、知识点、计划与任务
- 检测卷与作答、掌握度及 `knowledge_mastery_events`
- 复习日程与复习记录
- 讲解会话（题目讲解、知识点讲解及追问消息）
- 导师会话与消息
- 题目、测试数据、草稿、提交、判题结果与分用例结果、练习状态、错题

学习线（目标—知识点—检测—复习）与题库线（题目—提交—判题）分开存储。做题默认不写入知识点复习表，避免两套节奏互相覆盖。

### 3.4 关键规则（与实现一致，便于验收对照）

- 检测固定 5 题；已完成试卷再次提交返回冲突，避免重复改掌握度。
- 掌握度更新使用事件表；若快照为 0 但已有历史事件，则以前一次事件的新等级为基线，避免「有快照、无事件」被当成第一次测评而写零。
- 复习间隔：未通过缩短；连续通过按 3、7、14、30 天延长，有上限，不把知识点永久标为掌握。
- 判题：`system_error`（无 Docker / 无镜像等）不修改练习状态；编译失败、超时、运行异常不记为「答错」。
- 模型未返回合格 JSON 时，不保存该轮无效的导师消息或损坏的试卷。

## 4. 功能实现说明

### 4.1 账户与隔离

后端使用 HttpOnly 会话 Cookie 与 CSRF 头。前端登录后各页面通过当前会话访问数据。自动化测试覆盖「用户 A 不能读取用户 B 的提交与判题」。

### 4.2 目标、计划与检测

用户维护学习目标。生成今日计划时读取目标、已有掌握度与近期检测，调用 DeepSeek 产出任务列表。完成任务后可生成知识检测；客观题本地比对标准答案，多选须选项完全一致。提交后写入掌握度事件，并调用复习模块更新下一次日期。

### 4.3 复习与讲解

首页与复习列表只读已有日程，重复打开不会新建重复项，也不会调用模型。用户点击「开始复习」后才生成试卷；若已有未提交的 `open_quiz_id` 则复用。结果页可请求单题讲解。复习详情页可展开知识点讲解并追加追问，会话保存在服务端。

### 4.4 AI 导师

可按学习目标开启会话。发送消息时后端组装目标、知识点、掌握度、近期成绩等上下文。回复写入消息表。导师路径不修改掌握度，避免「聊一聊就升级」。

### 4.5 题库与判题

用户粘贴题面与输入输出样例。可选「AI 分析题目」得到分类建议；用户改过的分类在再次分析时保留。编辑器使用 CodeMirror，停止输入约 800ms 后保存草稿。提交只追加 `unjudged` 记录。判题服务查找 Docker，按固定参数 `docker run`，把源码经标准输入送入容器内的 runner，按测试点比较输出。DeepSeek 仅用于「AI 分析错误」，解释已有判题结果，不改写对错。

### 4.6 界面

侧边栏包含首页、学习目标、学习计划、AI 导师、复习、我的题库、错题本、学习档案、学习汇报（占位）、设置。支持主题切换。课堂与汇报页为后续阶段占位，避免假装已经实现。

## 5. 实现与测试

### 5.1 目录与职责

- `backend/app/routers`：HTTP 接口
- `backend/app/services`：计划、检测、复习、讲解、导师、判题等业务
- `backend/app/prompts`：模型提示词与页面逻辑分离
- `backend/judge`：判题镜像
- `backend/tests`：pytest
- `frontend/src/pages`：页面
- `start_*.ps1`：本机已安装环境下的启动脚本（不建库、不初始化官方账号）

### 5.2 测试策略

后端测试在独立测试库上进行，并用假函数替换模型调用与部分 Docker 执行，因此 `pytest` 不消耗 API 额度、不改正式 `studymate.db`。覆盖范围包括计划与检测、复习间隔、掌握度基线、讲解接口、账号隔离、判题状态机（含环境不可用时的 `system_error`）。

建议验收命令：

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest
```

健康检查：`GET /api/health` 应返回 `version` 为 `0.9.0`，`phase` 为 `9`。

### 5.3 运行与演示建议（6 分钟视频可按此裁剪）

1. 健康检查与注册登录  
2. 新建学习目标，生成今日计划（展示一次真实或预先准备的模型结果）  
3. 完成任务 → 知识检测 → 提交与掌握度变化  
4. 进入复习或题目讲解  
5. 导入一道简单 C++ 题，提交，展示 Docker 判题结果（若现场无 Docker，可播放预先录制片段并说明环境依赖）

## 6. 创新点、限制与后续工作

**特点：** 把「监督计划」和「安全判题」放在同一产品中；模型调用边界清楚（读页面不花钱、不改库）；判题与 AI 分析解耦。

**限制：** 当前以单机 SQLite 与开发服务器为主，不是公有云 SaaS；判题依赖 Docker Desktop；简答题评分仍依赖模型稳定性；课堂与汇报未完成。

**可延续：** 题目间隔复习、课堂讲解落地、学习汇报与计划修订确认流、更完善的学情可视化。

## 9. 总结

StudyMate 完成了从学习目标到检测复习、再到隔离 C++ 判题的主路径，并按阶段把数据、模型和容器边界写进实现。作为课程实践，其可验收性主要来自：克隆后可安装、接口与页面可演示、自动化测试不依赖外网模型、文档与源码一致。未完成的课堂与汇报在产品中保持占位，避免范围膨胀。
